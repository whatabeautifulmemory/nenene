# Nenene

법학논문을 쓰는 Electron 앱. `Nenene` 의 파이프라인(초고 → 인용 확보 → 적대적 검토 → 수정 → 조립)을
**구상 · 집필 · 원고** 세 단계의 데스크톱 UI로 감쌌다.

![원고](../docs/app-manuscript.png)

## 실행 · 빌드 · 패키징

```bash
cd app
npm install
npm start            # 빌드 후 실행
npm run dev          # vite HMR + electron (개발)
npm run selftest     # 브릿지·IPC·렌더러·코퍼스 자체점검

npm run dist         # .app 번들 (release/mac-arm64/)
npm run dist:dmg     # 배포용 dmg
```

패키징하면 코퍼스(법령·판례 인덱스 + partial clone)가 `Contents/Resources/corpus/` 에 들어가고 `LEGAL_AGENT_ROOT` 가 그리로 돈다.
**코퍼스를 넣지 않으면 패키징된 앱은 반쪽이 된다** — 모든 인용이 "코퍼스 밖"이 되고 앱의 유일한 hard gate 가 사라진다.

> 패키징된 앱에 인자를 넘길 때는 `--` 를 쓴다. `ELECTRON_RUN_AS_NODE=1` 이 설정된 셸에서는 `scripts/launch.mjs` 가 그 변수를 지우고 띄운다.
> 스크린샷·점검에 임시 워크스페이스를 쓰려면 `LPS_WORKSPACE=<폴더>` — 설정 파일에 저장되지 않는다.

## 세 단계

### 구상
![구상](../docs/app-conceive.png)

왼쪽은 **대화**다. 필자가 문제의식을 말하면 모델이 법적 쟁점으로 다듬고, 반론을 던지고, 필요한 판례·조문을 짚는다.
모델은 프로젝트의 조사 기록(`dossier.json` — 웹·백과·서지·판례)을 보고 답하며, 자료에 없는 판례·문헌은 ⚠ 를 붙인다.
답 아래 「조사 N건」을 누르면 그 턴의 조사 내역이 펼쳐진다 — 검색어(출처·각도·공급자·결과/남긴 수)별로 묶인 자료, 링크, 발췌, 못 읽은 링크.
이 기록은 메시지에 그대로 남는다(`dossier.json` 은 하루마다 다시 조사해 덮이고 번호가 바뀌므로, 턴의 기록은 메시지 쪽이 원본이다).
오른쪽은 **논문 설계 카드** — 제목·중심 논지·핵심 개념·연구질문·입장·범위·방법. 직접 쓰거나 「대화에서 설계 뽑기」로 채운다.
「집필 시작」이 이 카드를 들고 집필로 넘어간다. 규모(짧게/표준/길게)와 참고문헌 파일도 여기서.

### 집필
![집필](../docs/app-write.png)

13단계 스테퍼(조사 → 논지 → 목차 → 초고 → 인용 → 질문 → 연쇄 → 검토 → 보강 → 수정 → 재검증 → 인용 대조 → 조립)와 장 카드.
단계 아래 짧은 설명은 두 줄까지 보이고, 올리면 풀어 쓴 설명·상태·진행 내용이 말풍선으로 뜬다.
장마다 역할·분량·검토된 주장 수·상태(집필 중/초고/검토 중/수정됨)가 보이고, 펼치면 본문의 ⟦인용⟧ 이 상태 배지로 렌더된다.
원문을 못 구한 인용은 **본문 위 인라인 패널**로 묻는다 — 모달이 아니다. 오른쪽 서랍: 활동(도구 호출) · 인용(상태표) · 검토(주장별 판정·반대).
서랍 왼쪽 경계를 끌어 너비를 바꾼다(본문은 420px 을 남긴다, 두 번 누르면 처음 너비). 원고 탭의 서랍도 같다.

### 원고
명조로 렌더된 논문. 각주 위첨자를 누르면 각주로, 각주의 ↩ 로 되돌아온다. 「편집」으로 마크다운을 고치고 「저장」한다.
서랍: 각주(✓ 원문 확인 · ◐ 웹/공개자료 · ⚠ 미확보 · ✗ 코퍼스에 없음) · 참고문헌 · 검증(판정 분포·살아남은 반대·확인 필요 인용) · 실행(이 프로젝트의 runs).
DOCX(각주가 Word 각주로) · HTML(표·각주 포함) · MD 내보내기.

### 원문 찾기 브라우저 (사람에게 묻기)
원문을 구하지 못해 묻는 항목에는 「원문 찾기」 줄이 붙는다 — 후보 위치(KCI·법제처 등), DOI, 법령이면 법제처, 사건번호면 판례 검색,
논문이면 RISS·DBpia·구글 학술검색. 설명 안의 주소도 누를 수 있다. 누르면 **앱 안 브라우저**가 열린다: 로그인하거나 「원문 보기」를
눌러 원문을 띄우면, **내려받는 파일은 자동으로** 프로젝트의 `references/` 에 저장되고 그 질문의 답(「제공」)에 붙는다.
PDF 가 창 안(또는 페이지 안의 뷰어)에 떠 있으면 「이 페이지 넣기」가 그 파일을 받는다. 논문 소개 페이지가 원문 PDF 링크(`citation_pdf_url` 등)를
달고 있으면 그 PDF 를 받는다. 그 밖의 웹 페이지(법령·판결·기사)는 보이는 글(모든 프레임)을 `.md` 로 저장해 붙인다 — 초록·서지뿐인 소개 페이지는 원문이 아니므로 넣지 않는다.
읽을 수 있는 형식(PDF·DOCX·HTML·TXT·MD)만 붙이고, HWP 는 PDF 로 받으라고 알린다. `FileDown.do` 처럼 이름이 엉뚱한 파일은 서버가 밝힌 형식으로,
형식을 밝히지 않은 파일은 받은 뒤 내용(PDF·DOCX)을 보고 이름을 고친다. 짧은 오류·안내 페이지는 넣지 않는다.

**탭.** 페이지가 여는 새 창(`target=_blank`·`window.open`·POST 로 보내는 「원문보기」·빈 창에 글을 써 넣는 뷰어·⌘/가운데 누르기)은
같은 창의 **탭**으로 열린다 — 검색 결과가 덮이지 않고, 로그인 팝업이 끝나며 스스로 닫으면 그 탭도 닫힌다. 탭이 둘 이상이면 도구막대 위에
탭 줄이 생긴다(누르면 전환, ×·가운데 누르기는 닫기, 12개까지). 오른쪽 누르기 메뉴에 「새 탭에서 열기」·「링크 주소 복사」.
단축키: ⌘W 탭 닫기 · ⌃Tab/⌘⇧[ ] 탭 이동 · ⌘1~9 · ⌘L 주소 · ⌘R 새로고침 · ⌘[ ] 뒤로/앞으로(윈도우는 Ctrl·Alt+←→).
탭은 질문에 묶인다 — 다른 질문의 「원문 찾기」를 누르면 앞 질문의 탭과 받는 중인 파일을 닫는다.
POST 로 뜬 PDF 는 「이 페이지 넣기」가 같은 POST 로 다시 받는다(GET 으로 받으면 오류 페이지가 온다). 일회용 주소라 다시 받을 수 없으면
사이트의 「다운로드」 버튼을 누르라고 알린다.

페이지 쪽에는 preload·node 가 없고(sandbox) http(s) 만 열며, 권한 요청은 서비스 워커·PDF 뷰어까지 거절한다. **사람이 누르지 않은 내려받기**
(페이지가 스스로 파일을 받는 것)는 받지 않는다. 답하고 계속하거나 실행을 멈추면 창은 닫히고, 그 뒤에 끝난 내려받기는 붙지 않는다.

### PDF 읽기
`pdftotext`(poppler)가 있으면 그것을 먼저 쓰고, 없으면 **pdf.js 로 읽는다**(앱에 들어 있다 — 윈도우에서도 별도 설치가 필요 없다).
맥에서 Finder·Dock 으로 띄운 앱은 Homebrew 경로를 PATH 에 받지 못해 깔려 있는 pdftotext 도 못 찾던 것을 고쳤다(시작 시 `/opt/homebrew/bin`·`/usr/local/bin` 을 붙인다).

### 작업 기록 내보내기 (감사용)
제목줄의 시계 문서 아이콘. 프로젝트 하나에서 실제로 오간 것을 순서대로 한 파일에 편다 — 주제·배경·설정(키 제외),
구상 대화(턴마다 모델·토큰·조사 내역), 조사 자료, 설계, 그리고 실행마다 진행 기록(시작 설정·단계·도구 호출·질문과 필자의 답·완료/오류/중단),
검토 원장(주장·반대·판정·코드 강등), LLM 요청과 응답 원문(기록 단계의 4만 자 제한), 원고. 요약하지 않고 접어 둘 뿐이다.
HTML 은 스크립트가 없는 자기완결 파일(CSP 로 막음, 모든 글 이스케이프)이고, 저장 창에서 JSON 을 고르면 같은 기록이 원자료로 나간다.
법령·판례 목록이 없으면 앱이 켜질 때 받을지 묻는다 — 「나중에」면 홈 화면에 「받기」가 남고, 집필을 시작할 때 다시 묻는다.

## 구조

```
app/
├── src/main/              Electron main — 파이프라인이 여기서 돈다
│   ├── index.ts           창·부팅·자체점검·스크린샷·외부 링크 핸들러
│   ├── ipc.ts             renderer 가 보는 유일한 표면 (+ 구상 대화 chat:send · plan:propose · 프로젝트 조사 캐시)
│   ├── runner.ts          파이프라인 호스트 — composePaper 를 돌리고 stage/plan/section/cites/review 이벤트를 낸다
│   ├── settings.ts        설정 + safeStorage 키체인
│   ├── providers.ts       provider 카탈로그
│   ├── project.ts         프로젝트 폴더
│   └── export.ts          Markdown → DOCX(각주) / HTML(표·각주) / 실행 기록 HTML
├── src/preload/           contextBridge
├── src/shared/ipc.ts      main ↔ renderer 계약 (PaperThesis · PaperSection · CiteStatus · MainEvent · STAGES)
└── src/renderer/
    ├── App.tsx            셸 (설정·테마·프로젝트 목록 ↔ 작업 화면)
    ├── screens/           Home · Workspace(세그먼트로 세 단계)
    ├── stages/            Conceive · Write · Manuscript
    ├── lib/runState.ts    MainEvent → 실행 상태 리듀서 (지난 실행은 ledger.paper 로 복원)
    ├── lib/format.ts      한글 라벨 · 인용 톤 · 각주 파서
    └── components/        Stepper · SectionCard · CiteBadge · HitlPanel · PlanCard · Chat · Drawer · ChatMarkdown …
```

## 프로젝트 폴더

폴더 하나가 주제 하나다. DB 가 아니라 폴더라서 Finder 에서 열리고, 복사가 백업이고, git 에 넣으면 버전이 된다.

```
~/Documents/Nenene/
└── 2026-10-27-거주등록-신원체계/
    ├── project.json      주제 · 맥락 · 대화(chat) · 설계(plan) · 규모 · 원고 · 최근 실행
    ├── dossier.json      구상 대화가 보는 조사 기록 (하루 지나면 다시 조사)
    ├── references/       참고문헌 (pdf · docx · md · txt · html) — 원문 사다리가 가장 먼저 본다
    ├── sources/          파이프라인이 받아온 원문·조사 노트 (다음 실행에서 다시 내려받지 않는다)
    └── runs/<시각>/
        ├── ledger.json       설계·장·인용 상태표·주장별 반대·판정
        ├── paper.md          조립된 논문
        ├── report.md         검토 원장 보고서
        ├── calls.jsonl       모델 호출 기록 (전선 그대로)
        └── transcript.jsonl  단계·장·질문·답변 기록
```

| 프로젝트 (`project.json`) | 전역 (앱 설정) |
|---|---|
| 주제 · 맥락 · 대화 · 설계 · 규모 · 원고 | provider · 모델 · base URL · API 키 |
| 참고문헌 `references/` + 추가 디렉터리 | temperature · max tokens · 기본 규모 |
| 실행 기록 `runs/` | 역할별 모델(설계/수집/반대/판정/집필) · 연락처 이메일 · 워크스페이스 · 테마 |

삭제는 휴지통으로 보낸다. 영구 삭제하지 않는다.

## 확인된 것 / 확인 안 된 것

- `npm run build` (main · preload · renderer) 와 `tsc --noEmit` 통과.
- `--screenshot` 으로 세 단계 화면을 실제 실행 산출물(7장·인용 16건·주장 20개)로 렌더해 확인했다 (`docs/app-*.png`).
- 렌더러는 mock 된 `window.legal` 로 실행 중 이벤트(스테퍼·인라인 질문·인용 배지·완료 후 원고 전환·오류 배너)를 브라우저에서 확인했다.
- 확인 안 됨: 실제 모델로 앱 안에서 처음부터 끝까지 돌리며 HITL 패널에 답하는 왕복. 서명·notarization. Windows·Linux 번들.
